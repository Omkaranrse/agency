# ADR 0003: Isolated Docker Sandbox for Untrusted Code Execution

## Status
Accepted

## Context
Code generated by Builder agents (Astro components, TypeScript logic, `package.json` scripts) must be installed, built, and evaluated without threatening host security, accessing host files, or exhausting host resources.

## Decision
We implemented `DockerSandbox` fulfilling `SandboxPort`. Every run executes inside a containerized sandbox (`agency-sandbox:latest`) with:
1. Non-root user execution (`USER sandbox` uid 1000).
2. Dropping all Linux capabilities (`cap_drop=["ALL"]`).
3. Preventing privilege escalation (`no-new-privileges:true`).
4. Never mounting `/var/run/docker.sock`.
5. Mounting only a dedicated ephemeral host workspace directory (`/workspace`).
6. Disabling network access (`network_mode="none"`) during build and QA execution.
7. Enforcing resource limits: 1.0 CPU, 512MB RAM, 100 PIDs, 60s execution timeout.
8. Idempotent cleanup via `destroy()` and automated maintenance purge (`CleanupService`).

## Consequences
- AI-generated build scripts cannot access internal host resources or escape the container.
- Build resource consumption is strictly capped.
- Local tests can use `FakeSandbox` without requiring a live Docker daemon.
