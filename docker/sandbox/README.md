# Agency Docker Sandbox

This directory contains the specification and instructions for the **Agency Docker Sandbox**, an isolated execution environment designed to execute untrusted code and build web applications generated by AI agents.

---

## 1. Prerequisites

- **Docker Engine**: Version 24.0+ (or Docker Desktop on macOS/Windows).
- **Architecture**: `linux/amd64` or `linux/arm64` (Apple Silicon supported via native Node/Chromium builds).
- **Storage Driver**: overlay2 recommended.

---

## 2. Building the Sandbox Image

Build and tag the official sandbox image locally:

```bash
docker build -t agency-sandbox:latest -f docker/sandbox/Dockerfile docker/sandbox
```

To verify the built image and installed toolchains:

```bash
docker run --rm agency-sandbox:latest node -v
docker run --rm agency-sandbox:latest pnpm -v
docker run --rm agency-sandbox:latest git --version
docker run --rm agency-sandbox:latest npx playwright --version
```

---

## 3. Running Tests

### Unit Tests (Zero Docker Daemon Required)

Unit tests use a simulated Docker client interface and test path validation without needing Docker:

```bash
make test
# or directly:
cd backend && pytest tests/unit/infrastructure/sandbox/
```

### Integration Tests (Docker Daemon Required)

Integration tests verify end-to-end container creation, execution, path traversal rejection, and destruction against a live Docker daemon. They are marked with `@pytest.mark.docker`:

```bash
cd backend && pytest -m docker tests/integration/test_docker_sandbox.py
```

*Note:* If Docker is not installed or the Docker daemon is unreachable, these integration tests skip cleanly with a clear status report.

## 4. Sandbox Lifecycle

1. **`create`**:
   - Provisions a unique sandbox identifier (`sbx-<uuid>`).
   - Allocates a dedicated host workspace directory (`<base_workspace>/<sandbox_id>`).
   - Launches an unprivileged container running `sleep infinity` with strict resource limits and network isolation.
2. **`exec`**:
   - Dispatches argument-vector commands inside `/workspace`.
   - Enforces execution timeouts and caps maximum stdout/stderr bytes.
   - Captures and returns exit code, stdout, and stderr.
3. **`write_file` / `read_file` / `copy_out`**:
   - Validates all paths through `PathPolicy`.
   - Restricts operations strictly to the sandbox workspace.
   - Rejects directory traversal (`..`), absolute paths, and external symlinks.
4. **`destroy`**:
   - Stops and removes the container (`force=True`).
   - Deletes the host workspace directory.
   - Cleans up tracking metadata idempotently.

## 5. Security Controls and Resource Limits

| Control | Default Setting | Rationale |
| :--- | :--- | :--- |
| **User** | `1000:1000` (`sandbox`) | Prevents root-level operations inside the container. |
| **Privileged Mode** | `False` | Disables kernel and device access. |
| **Linux Capabilities** | Dropped `ALL` | Minimizes attack surface for kernel privilege escalation. |
| **Security Options** | `no-new-privileges:true` | Prevents setuid binaries from gaining elevated privileges. |
| **Network Mode** | `none` | Prevents outbound scanning, data exfiltration, or reverse shells. |
| **CPU Limit** | `1.0` CPU (`nano_cpus=1_000_000_000`) | Mitigates CPU exhaustion and denial of service. |
| **Memory Limit** | `512MB` | Protects host from memory leaks or fork bombs. |
| **PID Limit** | `100` | Prevents process exhaustion. |
| **Command Timeout** | `60s` | Guarantees worker thread responsiveness. |
| **Max Output Size** | `1MB` | Protects in-memory buffers from unbounded log output. |
| **Max File Size** | `10MB` | Prevents disk filling attacks. |

---

## 6. Network Restrictions and Limitations

By default, sandboxes run with `--network none`.

- **Package Installation Policy**: When build workflows require fetching packages via npm/pnpm, networking must be granted only during controlled provisioning phases or via a dedicated caching proxy.
- **Firewall & Host Isolation**: Docker container networking isolation does not replace host firewall rules. On Linux, iptables/nftables must ensure container subnets cannot access internal cloud metadata services (`169.254.169.254`), private VPC networks, or Docker host services (`localhost`).

---

## 7. File Path Security

All path inputs are validated via `PathPolicy`:
- **Absolute Paths**: Paths starting with `/` or Windows drive letters/UNC shares are strictly rejected.
- **Directory Traversal**: Paths containing `..` or normalizing to parent directories are rejected.
- **Symlink Protection**: Every path component is verified against symlinks to prevent escapes outside the workspace boundary.
- **Null-Byte Injection**: Paths containing `\x00` are rejected immediately.

---

## 8. Cleanup and Error Handling

- All sandbox resources are tracked by label `agency.managed=true` and `agency.sandbox_id=<id>`.
- Failures during creation trigger immediate cleanup of partially initialized containers or host directories.
- In the event of abrupt host or process termination that bypasses Python `finally` blocks, stale containers can be identified and reclaimed using the label query:
  ```bash
  docker ps -a --filter "label=agency.managed=true"
  ```

---

## 9. Safe Inspection of Sandbox Containers

To inspect an active sandbox container during local debugging:

```bash
# Locate container
docker ps --filter "label=agency.managed=true"

# Inspect resource metrics
docker stats <container_id> --no-stream

# View logs
docker logs <container_id>
```

Never attach to a running container with host socket mounts or elevation.

---

## 10. Threat Model & Residual Risks

> [!CAUTION]
> **Container containment is not an absolute security boundary.**
> Untrusted code execution carries inherent risks. Docker containers share the host Linux kernel. While capabilities, seccomp, and user namespaces substantially mitigate risk, kernel vulnerabilities may allow container breakouts.
>
> **Rules:**
> 1. Never mount `/var/run/docker.sock` into any sandbox.
> 2. Never mount host SSH keys, AWS credentials, or git configs into the sandbox.
> 3. Never pass production API keys or database connection strings to generated code.
